# Working Preferences Ledger

This file records preferences that help the Core OS adapt to the user's way of working.

## Rules
- Explicit preferences come from direct user instructions.
- Inferred preferences remain provisional until repeated evidence supports them.
- Record scope and evidence; do not generalize a one-off request.
- If an inferred preference would materially change an important decision, ask the user to confirm it.
- The user can correct or revoke any preference.
- Never store passwords, API keys, or unnecessary sensitive details here.

## Confirmed working principles
- Prefer practical, concrete, step-by-step guidance.
- Distinguish verified facts, third-party claims, hypotheses, and analysis.
- Do not overstate technical expertise or project maturity.
- Use deterministic calculations and tests before relying on LLM output.
- Measure baseline versus actual results where possible.
- Ask for human approval before consequential external actions.
